# SUR — handoff для следующего чата

## Текущее состояние: 0.4 / «Станция на связи», 2 октября 2026

Реализовано [ТЗ приключений и живого архива](MISSION_GAMIFICATION_AND_LIVING_ARCHIVE_SPEC.md). Пролог сохранён. После него **P / «Вместе» → «Новая глава» → «Открыть эти три приключения»** публикует главу; **J / «Истории»** открывает стол историй. Прежние консоль и журнал доступны из новых экранов. Основная реализация закоммичена и отправлена в main (`a9e0ecf`). 3 октября обнаружена подмена реального сохранения автотестами: прежнее утверждение о его неприкосновенности неверно. `cleanup_test_storage()` возвращал стандартные пути перед первым тестовым save. Семейный профиль восстановлен из неизменённой premigration-копии (имя, перо, сова, пройденный S00); прежние загрязнённые файлы сохранены отдельно. Исправление, проверенный runner и отдельная временная разработческая .app описаны в актуальном TEST_REPORT и руководстве разработчика. Никогда не запускайте тесты AppRoot на обычном семейном профиле.

Разработческая `.app` теперь по умолчанию начинает с частной копии актуального семейного сохранения. Меню F9 позволяет восстановить исходный снимок этого запуска либо начать с пролога/трёх миссий. Снимок включает `artifacts` и `launch_registry`, оригинал читается только Python-launcher и никогда не используется как рабочее хранилище игры. Все изменения теста удаляются при закрытии.

### Что реализовано

- FG01/FG11/FG08, схема контента 2, ревизия 2: по шесть этапов, бюджеты 40/60/40; frozen snapshot включает сцены и все зависимости. Испанская линия — 100 лексем, 20 конвертов, восемь видов механик в общем реестре. Реальные правильные ответы обновляют словарь; показ карточки сам по себе не считается знанием.
- Отдельная учебная игра Godot, пять подготовленных версий и исходные ZIP. Проверенный launcher сохраняет управляемые копии, сверяет контрольные суммы и запускает отдельный процесс. Готовый неизменённый пример не засчитывается как авторская премьера.
- Работы/версии/экспонаты/размещения/снимки; галерея 12 мест, отдельная комната данных `station_favorites:<profile>` с тремя местами, новые физические залы. Одновременно в дереве одна физическая комната. Водный диптих показывает именно две записи наблюдений, словарный альбом — статусы выбранной сохранённой версии.
- Шесть секретов, общий финал и тематические оформления без дополнительного XP. Галерея не заменяет прежнюю обсерваторию S10.
- Редактор этапов и зависимостей, preview в отдельном состоянии, импорт → черновик → явная публикация. AR02 «Три силуэта» проходит весь цикл без изменения сцен.
- Сохранение 1.3.0, исходная неизменяемая копия до миграции, защита неизвестной схемы, добровольное сопоставление старых действий новым этапам. Старый перенесённый экземпляр нельзя снова подтвердить или возобновить ради награды.
- Полная семейная копия состояния/медиа/исходников, фоновые операции с прогрессом и отменой. Локальный реестр доверенного запуска исключён; после восстановления нужна новая регистрация игры.

### Границы ответственности в коде

| Слой | Файлы и контракт |
| --- | --- |
| Контент | `content/CONTRACT.md`, `adventure_content.gd`: static `quests/get_quest/lexicon/chapter/secrets/example_package`; взаимодействия в словаре по ID |
| Правила и транзакции | `adventure_rules.gd`, `adventure_service.gd`, `activity_commit_service.gd`; `dispatch(candidate, operation, payload, profile_id, launch_verifier)` меняет только кандидата, без диска |
| Коллекции | `collection_service.gd`: версии, профильные комнаты, размещения, сохранённые выставки, доступные темы |
| UI | `adventure_hub/episode/editor`, `collection_browser`, `gallery_room`, общий `adventure_ui.gd`; `setup(snapshot, audio)` только отображает снимок, команды идут контроллеру |
| Интеграция | `adventure_controller.gd` + `app_root.gd`: кандидат → проверка → Save → замена live-state → refresh; ошибочная запись сохраняет прежнее состояние |
| Семья и файлы | `family_adventure_tools.gd`, `backup_service.gd`, `local_file_job.gd`: Nodes только на основном потоке, Thread/Mutex для копирования |
| Запуск | `launch_service.gd`: локальный экземпляр сервиса; идентификатор регистрации проверяется независимо при премьере и совместном подтверждении |

Не обходить stage attempts выдуманным `success=true`; UI сохраняет реальные ответы. `choice_context` выводится из подтверждённого snapshot. При повторной попытке смешанного словаря текущие ответы/подсказки очищаются, прошлые попытки сохраняются. Нельзя безусловно блокировать финальный Quest submit/confirm для schema2: они разрешены после всех обязательных этапов и выплаты ровно исходного бюджета; прямое milestone по-прежнему запрещено.

### Проверки и ограничения

Текущие результаты после финального прохода по качеству: **A27/B25/C30; core289; infrastructure81; content+launcher1033; journeys362; UI217; AppRoot65; authoring24; experience27; learning420 — без отказов**. Нагрузочный тест 100 миссий / 1000 работ / 20 залов пройден. [TEST_REPORT.md](TEST_REPORT.md) содержит конкретные замеры, границы тестов и команды. Реальные кадры — `screenshots/adventure/`; первый нативный короткий прогон — около 60 FPS, переходы в зал менее 0,25 с. Большой нагрузочный тест измеряет метаданные, не декодирование всех медиа.

Перепроверка обнаружила и закрыла четыре ошибки: двойную обработку J/P/Esc в AppRoot, потерю расстановки при восстановлении снимка другого типа комнаты, потерю `source_archive_kind` в версии премьеры и изменение readonly-профиля getters атласа. Не возвращать второй клавиатурный forwarding callback; тесты должны посылать события через Viewport, а не только вызывать методы экранов. Снимок зала и избранное несовместимы. WorldExplorer строится из копии состояния, старые quest mutation controls для readonly закрыты.

Вторая перепроверка закрыла потери текста при выходе в архив/прикреплении изображения, потерю редакторского черновика и выбранного этапа после preview, ложное закрытие после неудачного Save → Validate и повтор ID после удаления/добавления этапа. Редактор теперь выбирает сохранённые/импортированные истории, сохраняет текущие изменения перед переключением и создаёт следующую свободную ревизию для опубликованного/встроенного шаблона. Контекст preview переносится через `AdventureEditor.session_context()`; закрытие привязано к ответу именно на ожидаемый save. Новый `test_adventure_authoring.gd` проверяет этот путь через сигналы кнопок настоящего AppRoot и полный reload.

Третья перепроверка исправила восстановление удалённых залов: `retired_room_ids` и ID старых снимков запрещают повторную выдачу ID, `ensure_gallery` не воскрешает удалённую первую комнату. После удаления всех физических залов доступна кнопка «Вернуть сохранённый зал»; постоянное избранное не удаляется. Семейная очередь пропускает перенесённые экземпляры. Поиск архива учитывает замороженные названия историй и заметки версий. `CollectionBrowser.navigation_context()` синхронизирует текущую работу/версию/вкладку перед обновлением; исходный контекст открытия не должен возвращать пользователя к старой работе после команды. Отмена backup через Esc отдельно проверена и уже работала корректно. Предпросмотр повреждённого манифеста теперь использует ограниченное чтение JSON и проверяет массивы до обращения к ним; строка вместо `media` раньше вызывала runtime-ошибку.

Финальный проход по игровому опыту: компактный эпизод показывает реальные действия до словарика и критериев; все первые реплики видны при 125%. Диалог отправляет реальный `stage_attempt` на терминальном выборе, основной footer ведёт к следующей незавершённой сцене и лишь потом к завершению этапа. Успех раскрывает авторскую обратную связь, завершение — точную сохранённую работу через `work_requested`. Повтор после ошибки записи доступен без повторного диалога; «Продолжить позже» сохраняет `draft.interaction_id` и текст. При возвращённой совместной проверке семейная заметка видна, материалы открыты для редактирования. `test_adventure_experience.gd` (27 проверок) исполняется headless/нативно/из PCK; кадры — `screenshots/adventure/experience/`. Контент и начисления не менялись.

Готовый PCK экспортируется с preset `macOS`, JSON и ZIP включены; чтение контента, подготовка учебной основы, AppRoot65, experience27 и authoring24 проверены с `--main-pack`. Самостоятельная `.app` ещё не собрана: нужны export templates. Запуск проекта использует редакторный Godot; в экспортированной SUR доступен macOS `.app`-адаптер с XML Info.plist. Архив `.app` — бинарная сборка, не исходники. Учебный тест запускать только через `python3 learning_projects/station_light/tools/check.py --godot /opt/homebrew/bin/godot`.

Практические инструкции: [для семьи](adventure_family_guide.md), [для разработчика](adventure_developer_guide.md). Следующий содержательный шаг — совместное прохождение с Майей и наблюдение за длиной сцен, понятностью подсказок и интересом к своим работам. Технические тесты не заменяют эту проверку. Не расширять архитектуру и не переделывать принятую станцию без нового запроса.

## Что уже сделано

Рабочая Phase A — это одна атмосферная 3D-комната лесной станции в Эль-Больсоне с прологом S00 «Это моя станция». Игрок может оформить вывеску, выбрать экспонат, исследовать предметы, открыть журнал и настройки, разгадать первую тайну станции и увидеть переход мира из холодных сумерек в тёплое пробуждение. Состояние сохраняется локально.

Шкатулка с тремя дисками — **одноразовая первая сюжетная мини-миссия**, а не постоянный инструмент игры. Её логика: найти предмет → прочитать пожелтевшую записку → вывести три символа из образов → выставить код → станция просыпается. Правильная комбинация внутри реализации — `Гора / Ветер / Звезда`; интерфейс и журнал не должны раскрывать её заранее.

После пользовательской визуальной проверки убрана странная горизонтальная полоса за горами. В окне остаются луна, звёзды, горные силуэты и передний лес. Эта композиция принята как текущая основа Phase A.

Последний текстовый polish убрал из пользовательских текстов формулировки «пусковое реле», «замкнуть цепь» и «контакт замкнут». Смысл сохранён, но пробуждение станции звучит как маленькая тайна, а не инструкция электрика.

Phase B теперь тоже реализована. Есть каталог S00–S11, семь skill lanes, точная публикация ревизий через родительскую консоль, замороженные `QuestInstance`, submission без XP, взрослое подтверждение, идемпотентные награды, milestones, pause/resume, safety hold при отзыве, локальные артефакты, profile separation, backup recovery и безопасный author dialogue patch с preview/publish/rollback.

Короткая история Phase B закрывается существующей комнатой. Финальный основной квест **S10 «Восстановить канал»** выдаёт `observatory_view_01`: появляется табличка `ARCHIVO DE CAMPO • OBS I`, у двери обсерватории включается холодная подсветка, а клик по двери сообщает, что обсерватория открыта и следующая глава остаётся автору. **S11 «Мой первый патч»** — отдельная авторская задача и выдаёт `author_patch_accepted`; не путать эти два эффекта.

Phase C реализована как локальное расширение. Встроены 24 стартовые карточки, по 3 на каждое из 8 направлений. `goal_group = maya_first_goals` теперь содержит только настоящие главные цели; разминка FG10 из этой группы убрана. В журнале появилась отдельная вкладка «Активные приключения» с тремя текущими приоритетами в фиксированном порядке: **FG01 «100 слов в эфире»**, **FG11 «Первая своя игра»**, **FG08 «Река и водопады»**. Они не обходят родительский lifecycle: пока версия не опубликована взрослым, игрок видит ожидание открытия.

Растяжка вынесена из квестов в отдельный ритуал `movement_warmup`: 5 разных календарных дней, одна отметка за день, пропуски не обнуляют прогресс. Пятая отметка без XP выдаёт постоянный world effect `movement_ritual_light`; на станции появляется видимый знак/свет. Состояние хранится в `phase_c.rituals` и автоматически добавляется старым сохранениям через default merge.

Комната станции теперь поддерживает базовое свободное перемещение: W/S вперёд-назад, A/D поворот, Q/E стрейф. Существующая дверь обсерватории реально переводит игрока в `observatory_annex`, где есть дверь назад и отдельная более глубокая дверь с прежней проверкой `observatory_view_01`. При открытых модальных окнах движение блокируется. Также остаются три контейнера опубликованного контента (`radio_cafe`, `workshop_annex`, `field_archive`), экран исследования и редактор содержания в родительской консоли. Взрослый может создать семейный квест или открыть встроенный как следующую ревизию, сохранить `DRAFT`, затем отдельно опубликовать его через существующий lifecycle. JSON-пакеты проверяются целиком и импортируются атомарно только как черновики. Встроенные ревизии не перезаписываются; repeat-policy реально применяется в `QuestService.create_instance`.

Текущая schema save — **`1.2.0`**; загрузчик принимает `1.0.0`, `1.1.0` и `1.2.0`. Атлас хранится отдельно как data-driven карта с 11 точками и стартовым `atlas_unlocked = ["station"]`. Радио опционально получает прогноз Open-Meteo и может полировать формулировку через Gemini 3.8 во VibeProxy; основной игровой цикл остаётся офлайн.

## Что делать в начале нового чата

1. Сначала посмотреть `git status` и diff: репозиторий содержит незакоммиченные изменения Phase A, их нельзя считать мусором или откатывать вслепую.
2. Прочитать этот handoff, затем основной brief и README.
3. Проверить тесты и свежие скриншоты, не повторяя уже выполненный visual polish без причины.
4. Не переделывать Phase A, B или C с нуля: все три фазы уже приняты техническими тестами и визуальными кадрами.
5. Следующий этап: не переходить к Phase D/E преждевременно. Игре нужно дать время — пройти ряд миссий, собрать впечатления Майи от атмосферы и процесса, и только потом решать, какие авторские инструменты ей действительно нужны.

## Известные рабочие детали

`tests/visual_capture_runner.gd` сейчас реализован как `SceneTree`-скрипт и используется для автоматического снятия пяти acceptance-кадров. Не менять его только из-за отличия от ранней версии, если текущий запуск и захват работают.

`tests/phase_b_visual_capture_runner.gd` — отдельный нативный visual-runner Phase B. Он намеренно завершает S10 для кадра world-effect. Screenshot capture нужно запускать обычным нативным Godot/Metal, а не headless dummy renderer; runner сбрасывает save, поэтому запускать его на изолированной копии проекта с отдельным `config/name`.

`tests/phase_c_visual_capture_runner.gd` — отдельный visual-runner Phase C. Он публикует ES01, создаёт локальный семейный черновик FAM01 и снимает четыре состояния UI. Его также запускать на изолированной копии с отдельным `user://`, потому что runner сбрасывает тестовый профиль.

Godot создаёт `.gd.uid` и `.import` файлы. Не удалять их вслепую: сначала проверить `.gitignore` и принятые conventions проекта.

`scripts/services/audio_service.gd` содержит явную очистку процедурных WAV/playback-объектов в `_exit_tree()`. Она нужна, чтобы Godot 4.7.2/CoreAudio успевал отпустить активный зацикленный ambient stream до уничтожения ObjectDB; короткая `OS.delay_msec(20)` выполняется только при завершении приложения. Не убирать её как «лишнюю» без повторной проверки verbose-запуска.

Главный критерий проекта остаётся прежним: **одна красивая, цельная и живая игровая сцена важнее большого количества систем**. Долгосрочная цель — чтобы Майя постепенно стала соавтором и могла менять собственную игру.
