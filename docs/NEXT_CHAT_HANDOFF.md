# SUR — handoff для следующего чата

**Актуально на:** 26 сентября 2026 года
**Движок:** Godot 4.7.2 Stable
**Текущий этап:** Phase A, Phase B и Phase C завершены и проверены. Дальнейшие фазы авторства Майи (Phase D — конструктор, Phase E — программирование) временно **отложены**: приоритет отдан живому совместному прохождению миссий, исследованию мира и проверке игрового цикла.

## Что уже сделано

Рабочая Phase A — это одна атмосферная 3D-комната лесной станции в Эль-Больсоне с прологом S00 «Это моя станция». Игрок может оформить вывеску, выбрать экспонат, исследовать предметы, открыть журнал и настройки, разгадать первую тайну станции и увидеть переход мира из холодных сумерек в тёплое пробуждение. Состояние сохраняется локально.

Шкатулка с тремя дисками — **одноразовая первая сюжетная мини-миссия**, а не постоянный инструмент игры. Её логика: найти предмет → прочитать пожелтевшую записку → вывести три символа из образов → выставить код → станция просыпается. Правильная комбинация внутри реализации — `Гора / Ветер / Звезда`; интерфейс и журнал не должны раскрывать её заранее.

После пользовательской визуальной проверки убрана странная горизонтальная полоса за горами. В окне остаются луна, звёзды, горные силуэты и передний лес. Эта композиция принята как текущая основа Phase A.

Последний текстовый polish убрал из пользовательских текстов формулировки «пусковое реле», «замкнуть цепь» и «контакт замкнут». Смысл сохранён, но пробуждение станции звучит как маленькая тайна, а не инструкция электрика.

Phase B теперь тоже реализована. Есть каталог S00–S11, семь skill lanes, точная публикация ревизий через родительскую консоль, замороженные `QuestInstance`, submission без XP, взрослое подтверждение, идемпотентные награды, milestones, pause/resume, safety hold при отзыве, локальные артефакты, profile separation, backup recovery и безопасный author dialogue patch с preview/publish/rollback.

Короткая история Phase B закрывается существующей комнатой. Финальный основной квест **S10 «Восстановить канал»** выдаёт `observatory_view_01`: появляется табличка `ARCHIVO DE CAMPO • OBS I`, у двери обсерватории включается холодная подсветка, а клик по двери сообщает, что обсерватория открыта и следующая глава остаётся автору. **S11 «Мой первый патч»** — отдельная авторская задача и выдаёт `author_patch_accepted`; не путать эти два эффекта.

Phase C реализована как локальное расширение. Встроены 24 выбранные карточки из банка 56 (по 3 на каждое из 8 направлений, включая «Ролики»), три контейнера опубликованного контента (`radio_cafe`, `workshop_annex`, `field_archive`), экран исследования и редактор содержания в родительской консоли. Взрослый может создать семейный квест или открыть встроенный как следующую ревизию, сохранить `DRAFT`, затем отдельно опубликовать его через существующий lifecycle. JSON-пакеты проверяются целиком и импортируются атомарно только как черновики. Встроенные ревизии не перезаписываются; repeat-policy реально применяется в `QuestService.create_instance`.

Текущая schema save — **`1.2.0`**; загрузчик принимает `1.0.0`, `1.1.0` и `1.2.0`. Атлас хранится отдельно как data-driven карта с 11 точками и стартовым `atlas_unlocked = ["station"]`. Радио опционально получает прогноз Open-Meteo и может полировать формулировку через Gemini 3.8 во VibeProxy; основной игровой цикл остаётся офлайн.

## Что делать в начале нового чата

1. Сначала посмотреть `git status` и diff: репозиторий содержит незакоммиченные изменения Phase A, их нельзя считать мусором или откатывать вслепую.
2. Прочитать этот handoff, затем основной brief и README.
3. Проверить тесты и свежие скриншоты, не повторяя уже выполненный visual polish без причины.
4. Не переделывать Phase A, B или C с нуля: все три фазы уже приняты техническими тестами и визуальными кадрами.
5. Следующий этап: не переходить к Phase D/E преждевременно. Игре нужно дать время — пройти ряд миссий, собрать впечатления Майи от атмосферы и процесса, и только потом решать, какие авторские инструменты ей действительно нужны.

## Известные рабочие детали

`tests/visual_capture_runner.gd` сейчас реализован как `SceneTree`-скрипт и используется для автоматического снятия пяти acceptance-кадров. Не менять его только из-за отличия от ранней версии, если текущий запуск и захват работают.

`tests/phase_b_visual_capture_runner.gd` — отдельный нативный visual-runner Phase B. Он намеренно завершает S10 для кадра world-effect. Screenshot capture нужно запускать обычным нативным Godot/Metal, а не headless dummy renderer; runner сбрасывает save, поэтому запускать его на изолированной копии проекта с отдельным `config/name`.

`tests/phase_c_visual_capture_runner.gd` — отдельный visual-runner Phase C. Он публикует ES01, создаёт локальный семейный черновик FAM01 и снимает четыре состояния UI. Его также запускать на изолированной копии с отдельным `user://`, потому что runner сбрасывает тестовый профиль.

Godot создаёт `.gd.uid` и `.import` файлы. Не удалять их вслепую: сначала проверить `.gitignore` и принятые conventions проекта.

`scripts/services/audio_service.gd` содержит явную очистку процедурных WAV/playback-объектов в `_exit_tree()`. Она нужна, чтобы Godot 4.7.2/CoreAudio успевал отпустить активный зацикленный ambient stream до уничтожения ObjectDB; короткая `OS.delay_msec(20)` выполняется только при завершении приложения. Не убирать её как «лишнюю» без повторной проверки verbose-запуска.

Главный критерий проекта остаётся прежним: **одна красивая, цельная и живая игровая сцена важнее большого количества систем**. Долгосрочная цель — чтобы Майя постепенно стала соавтором и могла менять собственную игру.
