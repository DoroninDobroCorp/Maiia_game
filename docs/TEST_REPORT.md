# Отчёт о проверках SUR

## 0.4 — «Станция на связи» и живой архив

**Дата:** 2 октября 2026 года, America/Argentina/Salta (ночные логи UTC — 3 октября). **Среда:** MacBookPro17,1, Apple M1, 8 логических ядер, 16 ГиБ, macOS 26.4.1, Godot 4.7.2. Реализация проверялась относительно [ТЗ](MISSION_GAMIFICATION_AND_LIVING_ARCHIVE_SPEC.md). Дальнейшие разделы A/B/C ниже — исторические отчёты; измерения этого выпуска приведены здесь отдельно.

### Перепроверка на свежей копии

Повторный общий прогон выполнен в отдельной копии проекта с уникальным пользовательским каталогом: импорт редактором, Phase A/B/C, инфраструктура, ядро, контент/launcher, полные истории, UI, AppRoot, нагрузка и все учебные версии прошли без ошибок. Проверка кода и дополнительные сценарии затем выявили четыре пропуска в прежнем покрытии:

- **Глобальные клавиши обрабатывались дважды:** J/P/Esc могли открыть и сразу закрыть экран. Убрано повторное перенаправление `_unhandled_key_input` → `_unhandled_input`. Теперь AppRoot-тест посылает настоящие события через Viewport, проверяет старый журнал, семейную панель, настройки, ввод буквы J в заметку и сохранение/ошибку записи при Esc.
- **Несовместимый снимок мог очистить расстановку:** восстановление 12-местного зала в трёхместное избранное и обратный перенос отклоняются до изменения состояния. В UI показаны только снимки подходящего типа. Сам архив работ не удалялся.
- **Премьера теряла тип архива:** `source_archive_kind` теперь берётся из проверенной регистрации и сохраняется в версии работы. Тесты отдельно проверяют `project_source` и `application_bundle`.
- **Атлас менял профиль только для чтения:** старые getters добавляли поля в исходный Dictionary. Атлас теперь строится из отдельного снимка; переход из него к старым кнопкам изменения заданий запрещён для неподдерживаемого профиля.

Для каждого исправления добавлена воспроизводящая регрессия. До правок новые проверки действительно падали; после правок ядро проходит **274/274**, AppRoot **48/48**, UI **208/208**, полные истории **362/362**. Повторены затронутые Phase A/C и проверка PCK. Это уточняет прежнюю формулировку «всё готово»: успешный большой набор тестов не покрывал реальную цепочку клавиатурных событий и несколько границ между подсистемами.

### Автоматические сценарии

Вторая перепроверка проверяет переходы между формами, а не только правильность отдельных ответов. Воспроизведены и исправлены: потеря редакторского черновика/выбранного этапа после preview; ложное закрытие кнопкой «Проверить» после неудачного сохранения; повтор ID при удалении и добавлении этапа; потеря заметки при переходе из сравнения в архив; потеря текста новой версии при прикреплении изображения. Кнопка отказа от несохранённых правок снова доступна после перестроения формы.

В редактор добавлен недостающий рабочий выбор сохранённых и импортированных историй. Черновик открывается в своей ревизии, встроенная/опубликованная история — в следующей свободной, выше всех сохранённых номеров. Переключение сохраняет текущие изменения либо остаётся в прежней форме при ошибке. Импорт теперь возвращает к списку историй; проверен полный путь через реальные кнопки редактора, включая перезапуск AppRoot. Для добавляемого этапа используется рецепт выбранной истории.

Новый `test_adventure_authoring.gd` содержит **24 проверки**; расширенные UI — **212**, AppRoot — **51**, без отказов. Общая регрессия A/B/C, инфраструктуры, ядра, контента/launcher, полных маршрутов и нагрузки повторена на новой копии с отдельным пользовательским каталогом. Изменения этой перепроверки ограничены отображением, переходами и контроллером; правила награждения и учебные исходники не менялись.

### Третья перепроверка: архив, удаление и восстановление

Новые проверки воспроизвели две связанные ошибки залов: обновление мира заново создавало удалённую первую галерею; новый зал получал ID удалённого, и восстановление старого снимка заменяло его настройки. Теперь ID сохраняются в `retired_room_ids`, учитываются существующие снимки, удаление переживает refresh и перезапуск. Удалённый зал можно вернуть отдельной кнопкой даже после удаления последнего физического зала. Избранное станции остаётся постоянными тремя местами.

Также исправлены очередь совместного просмотра после переноса истории (старый экземпляр больше не предлагает недоступное подтверждение), поиск по замороженному названию приключения и заметкам версий, устаревший контекст архива после внутренних переходов. Создание зала из карточки работы остаётся в новом зале; после сохранения версии отображается её фактическая заметка. До правок регрессии по этим сценариям падали. Отдельно проверена уже корректная отмена восстановления через настоящее событие Esc: фоновой подмены прогресса после отмены нет.

Общий прогон выполнен в свежей копии `sur-third-audit-24my2_8k` с отдельным пользовательским каталогом. После последней правки контекста AppRoot повторён headless и нативно: **64/64**; ядро **289/289**, UI **215/215**, редактор **24/24**. Новые проверки включают отказ записи при удалении зала, сохранность работ и закреплённых версий, удаление без снимка, совместимость старого сохранения без маркеров удалённых ID. В повреждённом манифесте backup строка вместо массива вызывала runtime-ошибку ещё до запуска worker. Предпросмотр теперь читает JSON с ограничением размера и проверяет типы; ошибка объясняется в прежней панели без изменения прогресса. Правила начисления XP и учебные исходники в этой перепроверке не менялись.

### Финальный проход по детскому опыту — 3 октября

Проверялись реальные первые действия трёх историй, понятность ответа, возможность остановиться и увидеть собственную работу. В прежнем радиоэпизоде первое действие не помещалось без прокрутки даже при 100%: шапка, пояснения и словарик вытесняли реплики. Теперь компактная шапка и выбор сцены оставляют место действию; все три первых ответа видны при 1280×720 и масштабе 100%/125%. Словарик, контекст письма и критерии доступны ниже.

Завершающий выбор в диалоге отправляет настоящий ответ на проверку без дополнительного щелчка. Награда этапа по-прежнему фиксируется отдельно. После успешной сцены показана конкретная авторская реплика или результат и основная кнопка «Продолжить →»; проверенные сцены можно открыть снова. Единственный вариант темы выбирается переключением, без случайной ошибки из-за двух отмеченных флажков. Подсказка и её счётчик обновляются вместе. Возврат на доработку показывает семейную заметку и открывает прежний материал для редактирования.

«Продолжить позже» сохраняет сцену и текст перед выходом. При отказе записи ответа доступна повторная проверка, при отказе записи черновика экран не закрывается. После завершения кнопка «Посмотреть мою работу →» открывает реальную работу по её ID. После успешной проверки клавиатурный фокус переходит к продолжению, а не к закрытию. Завершённая сцена переигрывается без повторной награды. Контент, бюджеты и ранее замороженные определения не менялись.

Новый `test_adventure_experience.gd`: **27/27** — первые действия, все реплики, мягкая обратная связь при ошибке, пять слов через настоящий ответ, помощь, отказ записи/повтор, остановка/возвращение, личная карточка и повтор без начислений. До изменения расположения два визуальных критерия не проходили. Общий прогон выполнен в новой копии `sur-quality-final-oow_1y65`; после последних правок UI **217/217**, AppRoot **65/65**. ### Нативный интерфейс и производительность

Реальный запуск AppRoot после третьей перепроверки прошёл 64 проверки при 1280×720, включая UI 125% и события клавиатуры. Кадры находятся в [screenshots/adventure](../screenshots/adventure): станция, стол историй, путь, эпизод, архив, залы, наполненная галерея, диптих, игровой терминал, второй зал и редактор. В визуальном fixture используются только синтетические изображения во временном хранилище; проверены 12 совместимых размещений. Звук выключен; обязательные действия представлены фокусируемыми элементами, игровые механики имеют кнопки и не требуют перетаскивания.

Нативный Metal-прогон с измерением кадров `test_adventure_app.gd -- --render`, без одновременно запущенных тестов launcher: после 30 кадров прогрева измерены 180 кадров каждой сцены. Пролог — среднее **16,67 мс**, p95 **17,22 мс**; пробуждённая станция — **16,66 / 17,45 мс**; галерея — **16,67 / 17,15 мс**. Первый вход в зал с ожиданием двух кадров — **212,16 мс**, повторный — **180,51 мс**, бюджет 2 секунды соблюдён. Это короткое измерение тестовых сцен, не стресс-тест произвольных пользовательских медиа. Полный прогон только физической клавиатурой и длительный игровой сеанс ребёнка отдельно не проводились.

Масштабный тест метаданных, семь тёплых выборок: худшее открытие каталога приключений **83,091 мс**, семейного каталога **64,946 мс**, первой страницы архива **11,006 мс** (бюджет 500 мс); фильтры приключений **74,176 мс**, архива **7,758 мс** (бюджет 200 мс). Первая выборка каталогов — 80,627 / 58,885 / 9,305 мс соответственно. Этот тест не декодирует оригиналы и не измеряет FPS. В UI архив разбит на страницы, в галерее загружаются материалы текущего зала; все 1000 оригиналов одновременно не открываются. Холодное создание миниатюр всего большого архива отдельно не замерялось. В финальном дополнительном нативном прогоне среднее/p95: пролог 15,49/18,59 мс, пробуждённая станция 6,90/7,55 мс, галерея 6,90/7,49 мс; входы в зал 215,73/170,30 мс. В предыдущем прогоне зафиксирован один длинный кадр пролога 1110,86 мс; на повторном максимальный кадр составил 48,43 мс, такая пауза не повторилась. Причина единичной задержки не локализована; это ограничивает выводы короткого замера, а не скрывается средним FPS.

### Упаковка и воспроизведение

`export_presets.cfg` включает динамические JSON и ZIP. Экспорт `/tmp/sur-quality-final.pck` выполнен после последних исправлений; `test_adventure_pack.gd` подтверждает чтение контента и извлечение проверенной семифайловой основы непосредственно из PCK. С `--main-pack` проходят AppRoot **65/65**, детский путь **27/27** и редактор **24/24**. Нативный AppRoot также проходит 65 проверок; 11 кадров UI 125% пересняты без ошибок, [экран возвращения удалённых залов](../screenshots/adventure/deleted-halls-125.png) осмотрен. Редактор отдельно проходил 24 проверки в нативном Metal-запуске во второй перепроверке. Это доказательство упаковки ресурсов; самостоятельная `.app` не собрана, поскольку export templates в среде не установлены. Подпись и notarization не выполнялись.

Команды из корня проекта (полностью изолированный общий запуск описан в [инструкции разработчика](adventure_developer_guide.md)):

```sh
godot --headless --path . --script tests/test_adventure_journeys.gd
godot --headless --path . --script tests/test_adventure_ui.gd
godot --headless --path . --script tests/test_adventure_app.gd
python3 learning_projects/station_light/tools/check.py --godot /opt/homebrew/bin/godot
godot --path . --resolution 1280x720 --script tests/test_adventure_app.gd -- --render
```

Учебный `test_learning_game.gd` напрямую из SUR намеренно возвращает ошибку; нужен `check.py`. Адаптер `.app` проверен на macOS с XML Info.plist; запуск исходного проекта требует редакторный Godot. Архив бинарной `.app` помечен `application_bundle`, исходники проекта — `project_source`. Реестр доверенного запуска не переносится семейной копией: восстановленную игру нужно зарегистрировать заново. Педагогическая увлекательность и удобство самостоятельного прохождения Майей требуют наблюдения в семейной игре; автоматические проверки этого не доказывают.
